## 2. ★ 这一轮学到的硬事实（都带证据，别再重推）

### 2.1 「禁止回弹」为什么必须删（已验）

听歌页的**下拉关闭是经过那条列表接管的**：列表在顶部时把下拉让给窗口。
钉住之后列表**没有任何内部可滚范围**（`content.h == bounds.h`）⇒
`alwaysBounceVertical = true` 时拖动只能落到"让位"那条路 ⇒ 关得掉；
写成 `false` 就**既不滚也不让位** ⇒ 窗口永远收不到那次下拉 ⇒ **播放器划不掉**。

* 日志 41（全量 37 份里唯一 `bounce=off`）：`[OneScreen] 已关掉列表的回弹（alwaysBounceVertical=false）`；
* 日志 43（修完）：`bounce=on` + 用户实测能退出。
* **pw 也从没碰过它**：它只改 `contentInset.bottom`，并在 `PlayerField.x` 给背景场**向上多铺 200pt**，
  注释写着那是"the pull that dismisses the player"。

⇒ **纪律：在听歌页上，`alwaysBounceVertical` 与"滚动"都别碰；要一屏不滚就只改 inset。**

### 2.2 定向转储（`[NPVTree]`）——以后取证的默认手段

`ViewTreeDumper.setPage(_:)` 由**页面自己的 hook** 登记页根（听歌页 =
`NPVScrollViewControllerHook`），在登记过的页上：
**只走这一页子树、预算 1200、tag 用 `[NPVTree]`**；其它屏照旧 `[Tree]`（整窗 400 节点）。
**为什么必须**：听歌页一棵树约 **800 节点**，整窗 BFS 的 400 预算永远够不到底部那一坨
—— 日志 40/41 的 20 份树**每份正好 402 行**就是这个原因。

### 2.3 pw 的播放页结构（读源码得来，GPL-3.0 那侧）

`Player.h` 是总纲，原话：*"Spotify's full screen player **kept** … Every control stays Spotify's own …
**one screen with nothing under it**: every card is collapsed and the player does not scroll.
**The lyrics come to the player itself, the way the Music app shows them, when the lyrics glyph is
tapped.**"*

| 文件 | 做法（我们照抄的那部分） |
|---|---|
| `PlayerCards.x` | 每张卡报 0 高 —— **和我们一样**（连 hook `preferredLayoutAttributesFittingAttributes` 都一样） |
| `PlayerScroll.x` | 钉在顶部、只改 `contentInset` —— **和我们一样** |
| `PlayerArtwork.x` | 封面圆角连续 + 柔和阴影 + **暂停缩放 0.84**；把封面下那行歌词预览藏掉 |

### 2.5 歌词的三个真 bug（日志 45 判读，已修未验）

1. **选歌只比时长**（±5s + 取第一个）⇒ 翻唱/伴奏/同曲异名会被选中 ⇒ 用户"歌词全是错的"。
   **旧日志（readlog 10/11/18）证明这从最初就是这样**，不是新引入的；只是换成 NetEase 单源后暴露。
   → 现在要求**歌手 + 时长都对得上**（歌手名来自 metadata 的 `artist_name` / `artist_name:1`…）。
2. **`<Music>` 被当正文**：网易用尖括号占位标间奏，而既有 9 条"标注行"规则只认 `[方括号]`/`♪`。
   → `LyricsMarkerFilter` 新增**尖括号占位行**，网易两条建行路径都过滤（**丢整行**，不留空行）。
3. **"只画逐词"门禁太严**：Spotify 自己的卡片**行级也渲染**，而那张卡正是被「一屏」折掉的
   ⇒ 没逐词的歌**两边都空**。→ 放宽到行级（`hasUsableWordLevelData || hasUsableLineLevelData`）。

## 4. ★ 本机环境的纪律（这一轮又踩了两次，务必照做）

1. **五条自检不做类型检查**（`orion_hook_guard` / `swift_brace_check` / `swift_member_check` /
   `l10n_lint en` / `l10n_lint zh-CN`）。它们能抓"缺 import Orion"这类，**抓不到**下面两类：
   * **逐成员初始化器是位置敏感的**：给 SwiftUI 视图加字段后，参数顺序**必须与属性声明顺序一致**。
     CI 原话：*"argument labels do not match; expected …previewHeaderInset:onSeek:…trackArtist:
     transparentBackdrop:clock:…"* —— 加字段后**去读一遍结构体属性顺序再写调用点**。
   * **`@MainActor` 类型不能在非隔离上下文里被调**：门面/宿主标了 `@MainActor`，
     调用点就得在 MainActor 上；**Orion 的 hook 方法不能加 `@MainActor`**
     （代码生成器会拼出 `@MainActoroverride`）⇒ 用
     `onMainThreadSync { … }`（[`LyricsChromeVisibility.swift:25`]）。
     **提交前把新 API 的所有调用点列出来逐个看。**
   * 附带：逐成员初始化器失败后，**紧邻几行会跟着报"推断不出类型"**（如 `= .clear`）——
     那是恢复状态，**先修第一条**。
2. **查历史证据要同时看两个目录**：`C:\dsh\ipa\`（09-30 之后，`eeveespotify_debug_shared N.log`）
   与 **`C:\dsh\readlog\`**（09-26/27，`eeveespotify_debug N.log`）。这一轮又栽了一次
   （只翻 `ipa` ⇒ 差点得出"以前没这问题"的错误结论）。
3. `pwsh` 必须带 `sandbox_permissions: "danger-full-access"`（否则 `0xC0000142`）；
   控制台 GBK ⇒ 中文输出**写进 UTF-8 文件再 read**；PowerShell 里**别在双引号字符串里放中文双引号**
   （`"…"…"` 会把解析器搞崩，用 `「」`）。
4. 删/改**别人的视图**时：只改**透明度**或**加自己的子视图**；**不 hidden、不移除**（Encore 布局会因 hidden 重排）；
   记好还原表；几何一律 `transform`（**不动约束** —— stack view 会把约束写回）。
5. 递归走别人的子树要**有界**（`maxNodes`），并且**别碰非图形的叶子**。
