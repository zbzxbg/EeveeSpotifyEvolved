## 0.5 ⚠️ flag 通道：更正 + 已修（2026-10-01 晚）

**先更正**：§2.9 那个"Flag 覆盖确诊空转"的结论**是错的**。同一个仓库里就有反证：

| 日志 | `[Flags]` 条数 |
|---|---|
| `C:\dsh\readlog\eeveespotify_debug 5/6/7/8/9/11/13/14/16/17.log`（09-26/27） | **29 / 61** |
| `C:\dsh\readlog\eeveespotify_debug 19.log`（**09-30**，9.1.86 / iOS 27 / 同一台机） | **61 条真 scope+name+取值** |
| `C:\dsh\ipa\eeveespotify_debug_shared 9~14.log`（**10-01**） | **0** |

（09-26 之后那批在 `C:\dsh\readlog\`，**不在** `C:\dsh\ipa\` —— 只查后者就会得出"从来没有"的错误结论。这个坑记住了。）

**真因**：`assignedValues`（flag 清单）在没有网络 body 时只有一个来源，而那个来源被死锁了 ——
`cachedCustomizeData` **唯一**的写入点在 `SpotifyResponsePatcher.patch()` 的 customize 分支里，
而 `patch()` 只有**已经拿到 body** 之后才会被调用。冷启动第一个 customize 通常是 **304 无 body**
→ 缓存永远是 nil → 304 兜底（`DataLoaderServiceHooks.x.swift` 的 304 分支）没有可回放的东西
→ `modifyRemoteConfiguration()` 一次都不跑 → `[Flags]` 全灭、**所有 flag 替换（含内置那批
crossfade/automix/队列限制/歌词入口）一起静默失效**。

**已修（未编译）**：

1. `SpotifyResponsePatcher.seedCustomizeDataIfNeeded()`：启动时用随包 `.bnk`
   （`resolveconfiguration_9_1_76.bnk`，实测 **1089 条 assignedValues**）构造一份
   `CustomizeMessage` → 填进 `cachedCustomizeData`。只填空位，真 body 一到即被替换。
   调用点在 `Tweak.x.swift` 的 `init()` 里（`activateEeveeCrossfadeForce()` 之后）。
2. 「转储 customize 响应体」抓取开关（设置 → Debug）：把**原始** body 以 base64 写进调试日志，
   用来把 9.1.76 的旧快照换成**这版**的真清单。
3. 新工具 `Tools/eevee-hookfinder/bnk_from_customize_dump.py`：把抓到的 base64 剥掉
   `CustomizeMessage`/`UcsResponse`/`ResolveResponse` 三层壳，还原成 `.bnk`；
   `--inspect` 能直接数 assignedValues 条数。

**验证（2026-10-01 日志 16 —— ✅ 已通过，三段证据全齐）**：

```
05:19:53 [CustomizeSeed] 种子就绪 … 1089 条 flag（随包快照，非服务端当前下发）。下面那批 [Flags] 行就是**从这份种子**跑改写时打出来的。
05:19:53 [Flags] lyrics flag — scope=ios-feature-lyrics name=enable_lyrics bool=true      ← 种子改写真的跑了
05:19:53 [Flags] replacement ios-feature-lyrics.lyrics_entry_point_enabled — 1 match(es)  ← 替换命中
05:19:53 [CustomizeSeed] 种子已改写好并入袋：101417 字节。
05:19:56 [Flags] npv flag — scope=ios-feature-comments name=enable_comments_card bool=true ← 服务端真 body 到了
05:19:56 [HCUS] Patched customize                                                            ← 真 body 走 patch() 被改写
```

对照：日志 15（同一次编译、改动之前）里种子只打了 99451 字节、**`[Flags]` 0 行**；
日志 16（新包）**99451 → 101417 字节**（+1966 = 替换写进去的东西）、`[Flags]` 大批出现。
⇒ 「Flag 覆盖」通道**从假开关变成真开关**，内置那批 flag 替换（crossfade / 队列限制 / 歌词入口 /
各种分享位）也一起恢复。§2.9 那段旧结论可以彻底删了。

**顺带确认的两件小事**：
1. 冷启动时 customize 请求可能**早于种子入袋**（日志 16 里 05:19:49~52 有几条 `Patched customize`
   在种子之前）—— 无害，种子随后入袋，之后的 304 就能回放。
2. 种子里快照类 flag 的**状态是 9.1.76 时期的**（例：`lyrics_entry_point_enabled=false` 是快照自带值），
   真 body 一到即被服务端现值覆盖并再走一遍改写。

**bootstrap 没有种子**（它是另一种 message），09-30 的日志里 `[HCUS] Patched bootstrap` 从来没出现过
—— 那是另一件事，别和 flag 混。

### 7.2 新纪律（都是这次的 CI 学费，写下来免得再交）

1. **`.x.swift` 开头必须 `import Orion`。** 漏了它，Orion 的类型进不了编译单元，会炸出
   `cannot find type 'HookGroup' / 'ClassHook'` → `_Glue` 不符合协议 → `orig`/`target` 找不到
   → `#selector` 未暴露给 ObjC …… **一长串看起来毫不相关的错，其实只有一个根因**。
   验证：`python Tools/eevee-hookfinder/orion_hook_guard.py`
2. **HookGroup 必须真的定义。** `typealias Group = XxxGroup` 里那个名字没定义时，
   错误会被 Orion 的连锁报错盖住。
3. **deployment target 是 iOS 14，不是 15。** `UIButton.Configuration` / `UIButton.configuration`
   是 iOS 15+ → 编译期错误（不是运行期判断能救的）。用 `setImage(_:for:)` + `tintColor`。
   本仓库早就在 SwiftUI 那侧踩过同类坑（`foregroundStyle` 是 iOS 15+ → 一律用 `foregroundColor`）。
4. **`heightAnchor.constraint(equalTo:)` 只能配 `NSLayoutDimension`。** 想要"安全区 + 62"
   要写 `equalTo: safeAreaLayoutGuide.heightAnchor, constant: 62`（我第一次写成 `topAnchor`）。
5. **hook 方法（及其直接调用链）上不写 `@MainActor`** —— 这是仓库成文的规矩
   （`LyricsChromeVisibility.swift:3-17`）：Orion 按源码文本拼 `override`，`@MainActor` 会拼出
   非法属性；而且生成的跳板是非隔离的，同步调隔离函数又是隔离违规。
   **正确做法：hook 方法保持非隔离，方法体里 `onMainThreadSync { … }`** —— 现成 helper，
   不要自己写 `MainActor.assumeIsolated`。
6. `if let` 绑过的值不要再写可选链（`shell?.foo()` → `shell.foo()`）。

### 7.3 本机可跑的两个编译前哨

| 脚本 | 挡什么 |
|---|---|
| `Tools/eevee-hookfinder/orion_hook_guard.py` | ①缺 `import Orion`；②`typealias Group` 指向的 HookGroup 不存在；③`orig.*` 转发缺失 |
| `Tools/eevee-hookfinder/swift_brace_check.py` | 括号/字符串配对（**认 Swift raw string `#"..."#`**，否则正则里的方括号会误报） |

改完 `.x.swift` **先跑这两个再推 CI**（每次编译都很贵）。
