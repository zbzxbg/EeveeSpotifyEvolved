3. **水印消失**：Spotify 原生歌词卡/全屏页底部只写源名，不再有 `(EeveeSpotify)`。

5. **没有时间轴的歌**（如《Psycho》）：应**列出全文并可滚动**，而不是只显示一句话。

7. **控件条两条竖线**：分享键对齐 shuffle、歌词键对齐 play。

## 4. 要求与纪律（**这一段是本会话最有价值的部分**）

### 4.1 编译/验证这条链

1. **本机没有 Swift 工具链** ⇒ 类型检查**只能靠 CI**。六条 Python 自检**不做类型检查**。
2. ★★ **改完 Swift 必须跑一次 `Build IPA — patched`**（`ipa_url` 可留空：`Build .deb` 那步无条件跑，等于把全部 Swift 编一遍）。理由：这次的 `cannot find 'romanization' in scope` 就是六条自检 + 肉眼都抓不到、只有编译器能抓的那类错 ✗。
3. **CI 红一次 ⇒ 加一条自检规则**（已有：③ 跨文件 `private` 名、④ `UIView` 上没有 `UIControl` 方法、⑤ `body` 里简写绑定引用了不存在的名字）。新规则必须**两向验证**：干净仓库 0 处 + 同形 fixture 精确报错并 exit 1。
4. **宁可漏，不误报** —— 所有规则都只做"能判准的那一小块"，宁可放过。
5. 脚本化改文件之后，**直接读文件核对**（不能信脚本自己的计数：这次它报"替换 0 处"、其实已经改了 ✗）。

### 4.2 本地化

6. **英文只由 `en.lproj` 单点提供**（政策 B）：其它语言缺键自动回落英文；**逐字英文副本是冗余，要删**。
7. `Tools/l10n_lint.py`：**重复键 = error**（后写生效会静默盖掉前一条）、extra 键 = error、未翻译 = informational、格式参数差异 = warning。
8. `.strings` 的解析要注意：键**可以不带引号**（老式写法）；`//` 行注释必须先剥。
9. 新增/修改文案后跑：`python Tools/l10n_lint.py --locale en --quiet` 与 `--locale zh-CN --quiet`。

### 4.3 版本与 API

10. **最低 iOS 14**（`control` / `Makefile`），**推荐 iOS 26+**；**不要为了液态玻璃提高最低版本**（玻璃靠运行期反射拿）。
11. 因为底线是 14，**禁用 iOS 15+ API**（`UIButton.Configuration`、SwiftUI `foregroundStyle` 这类会编译错）。

### 4.4 改代码的习惯

12. **一次只改一件事**；改之前**先量证据**（照片像素 / 真机日志），别凭观感。
13. 日志与提交信息**一律英文**；代码注释中文可以（仓库内部笔记也是中文）。
14. 改**别人（Spotify）视图**要极端保守：只做 transform / 透明度，动完要能**完全还原**；不碰私有 API。
15. 改 `UserDefaults` 默认值**只影响没写过该键的用户** —— 自己设备上要验证就得先删键或在设置里手动翻一次。
16. 环境：`pwsh` 每次调用都要带 `sandbox_permissions: "danger-full-access"`，否则 `0xC0000142`。
